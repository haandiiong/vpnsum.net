先记录完整错误提示，再区分“配置没有导入”“节点不能连接”和“应用流量没有进入客户端”。这三种故障发生在不同环节，反复重装通常会丢掉排查线索。

适用范围：Clash Verge Rev、FlClash 等读取 Clash/Mihomo 配置的客户端，以及使用自身配置格式的其他客户端。本文按官方说明整理排查方法；下方案例是操作示例，不是本站的服务性能实测记录。

## 先按症状选择入口

| 你看到的情况 | 先看哪里 | 本次检查的目的 |
|---|---|---|
| 更新提示401、403或404 | [账号](#第一步检查账号)与[订阅请求](#第二步检查订阅) | 确认请求被拒绝、地址失效还是服务异常 |
| 配置解析失败、无效格式，或导入后没有节点 | [格式与客户端](#第三步检查格式和客户端) | 确认导入的是客户端支持的配置 |
| 一个节点超时，其他节点可用 | [故障范围](#第四步区分单节点和全局故障) | 避免为一个节点重置整套配置 |
| 所有节点超时，但网页订阅能正常更新 | [故障范围](#第四步区分单节点和全局故障)与[网络对照](#第七步更换本地网络) | 区分连接链路、账号限制与本地网络 |
| 浏览器可用，某个应用不可用 | [代理模式](#第五步检查代理模式) | 检查应用流量是否进入客户端、命中了哪条规则 |
| 日志出现域名解析失败 | [DNS](#第六步单独处理dns) | 先确认解析环节，避免随机替换DNS |
| 开启TUN或第二个VPN后断网 | [代理模式与恢复](#第五步检查代理模式) | 恢复之前可用的连接方式 |

### 开始前保留三项信息

1. 记下操作时间、客户端及核心版本、系统版本和使用的网络。
2. 在客户端的日志页复现一次错误，保留对应时间的提示；需要导出Clash Verge Rev日志时，打开「设置 → Verge高级设置 → 日志目录」，按[官方导出说明](https://www.clashverge.dev/guide/log.html)获取当天文件，并区分GUI日志与`service`目录下的内核日志。
3. 保留原配置和当前可用节点。暂时不要卸载客户端、删除全部配置或同时调整DNS、TUN和规则。

共享材料前遮住订阅链接、二维码、认证参数、账号和私人访问记录。只打开调试日志复现所需的一小段时间，之后恢复日常日志级别。

## 第一步：检查账号

打开服务后台的套餐或使用情况页面，核对到期时间、剩余流量、设备数及同时在线IP限制，再查看维护公告。能登录后台不等于套餐仍可使用。

**正常结果：**套餐在有效期内，有可用流量，未超过服务明确规定的连接限制。此时进入第二步。

**不正常时：**先解决后台明确提示的问题，再更新订阅。只有地址已泄露、被服务端撤销或后台要求更换时，才重置订阅；重置后旧地址可能失效，需要同步更新所有设备。

## 第二步：检查订阅

从后台与客户端对应的“订阅”入口重新复制完整地址，核对没有漏掉认证参数、添加空格或误复制登录页面。不要把私有地址交给在线检测、转换或测速网站。

在客户端中手动更新一次，记录更新结果和时间。浏览器访问失败只能作为线索：服务可能对浏览器和客户端采用不同的访问规则；同样，HTTP请求成功也不代表返回内容就是有效配置。

| 请求或更新结果 | 能说明什么 | 下一步 |
|---|---|---|
| 401 | 请求缺少服务认可的有效认证 | 核对后台新复制的地址和套餐状态；持续失败时提供错误给服务方 |
| 403 | 服务端或中间防护拒绝了本次请求 | 查看服务公告与访问限制，用同一客户端换网络对照；不凭这个状态断言套餐过期 |
| 404 | 请求地址对应的资源不存在，或服务选择这样响应 | 核对后台是否更换了订阅入口，不自行猜测路径 |
| 429 | 请求过于频繁，或触发了服务的请求限制 | 停止连续更新，按响应或服务公告的等待时间重试 |
| 5xx | 服务端或网关未正常完成请求 | 保留时间和错误，查看公告；换设备对照仍失败时联系服务方 |
| 请求超时、连接失败 | 还没有取得可判断的配置响应 | 进入第七步做网络对照，不先认定格式错误 |
| 更新成功，但随后解析失败或节点为空 | 取得了响应，配置仍可能不兼容或没有可用节点 | 进入第三步检查格式与当前启用的配置 |

**正常结果：**客户端显示更新成功，更新的配置与当前选中配置一致。然后核对节点列表；旧配置仍被启用，是“更新了但没有变化”的一种常见排查方向。

## 第三步：检查格式和客户端

| 配置或入口 | 对应路径 | 检查重点 |
|---|---|---|
| Clash/Mihomo YAML | Clash Verge Rev、FlClash | 后台选择对应订阅类型，检查代理节点及当前配置是否启用 |
| sing-box JSON | sing-box 客户端 | 使用服务提供的兼容JSON配置；不能把Clash YAML直接当JSON导入 |
| 单节点分享链接或其他订阅 | 以客户端官方支持格式为准 | 区分节点链接与完整配置，不靠修改文件后缀转换格式 |
| 只有官方专属客户端的服务 | 使用该服务明确支持的客户端 | 登录地址和账号不能替代通用订阅 |

遇到“配置解析失败”“不支持的字段”时，先核对服务提供的格式，再查当前客户端和核心版本。如果服务明确要求新版本，备份后从官方发行页升级；升级客户端不会自动把错误格式转换成正确格式。

若日志或响应预览显示HTML登录页、验证页或错误页，回到第二步检查请求。不要把这类内容保存成YAML或JSON后继续导入。

**正常结果：**配置能被读取，存在可选节点或策略组，选中配置已生效。只有策略组但没有可用代理节点时，应继续核对服务的配置内容。

## 第四步：区分单节点和全局故障

先固定一个测试目标和同一网络，选择两个不同的普通节点分别重试。不要连续更换目标、规则和节点，否则无法比较。

| 对照结果 | 优先排查 | 下一步 |
|---|---|---|
| 节点A失败、节点B可用 | 节点A或它所在的线路 | 使用B作为临时备用，记录A的节点名称与时间 |
| 延迟测试失败，但目标网页实际可用 | 延迟测试地址或测试方式 | 检查测试目标；“全红”不能单独证明所有业务不可用 |
| 所有节点和实际访问都失败 | 账号限制、配置、客户端核心或本地网络 | 核对前三步，再做第七步对照 |
| 同一账号在另一台设备可用 | 当前设备、客户端或配置差异 | 对比客户端版本、模式和VPN状态 |
| 不同设备、不同网络都失败 | 服务状态、账号或共用配置 | 查看公告，带对照结果联系服务方 |

确认连接要看实际网页或应用，并观察客户端是否产生对应连接。延迟数值、一个测速结果和长时间稳定性是不同问题。

## 第五步：检查代理模式

先尝试访问一个目标，再观察客户端的连接列表或日志：

1. **没有对应连接：**检查系统代理是否开启，或Android客户端是否排除了该应用。部分程序不使用系统代理；需要TUN时，先按[Clash Verge Rev教程](/guides/clash-verge-rev/)检查服务状态，或按[Android教程](/guides/android-proxy-client/)核对VPN授权。
2. **有连接，但走了直连或不合适的策略组：**查看命中的规则和选中节点。只在短暂对照中切换为客户端提供的全局代理模式；成功后恢复原模式，再处理对应规则。
3. **有连接、已选代理节点，仍然失败：**保留错误，回到第四步比较节点，并检查是否为某一个网站或账号的问题。

### 开启TUN后断网怎样恢复

先关闭刚开启的TUN，恢复之前可用的系统代理或连接模式。如果退出客户端后浏览器仍连不上，而系统代理还指向已停止的本地端口，清除这项残留代理；不要清除单位要求的代理或管理配置。确认基础网络恢复后，再按客户端官方说明检查服务、权限和配置。

Android的同一用户或工作资料只能有一个活动VPN服务；另一个VPN、部分去广告或防火墙应用可能占用它。仅在确认该应用不是当前所需连接时停止它，再授权目标客户端。不要一边运行多个接管网络的客户端一边修改分流。

## 第六步：单独处理DNS

先找与本次访问对应的日志：只有明确出现域名解析失败、解析超时或相关DNS错误时，才把DNS作为主要排查方向。网站打不开也可能来自规则、节点、TLS或目标服务限制。

1. 保存当前配置，记录DNS报错的域名与时间。
2. 使用已知可用的配置或客户端推荐的默认设置作对照；不要直接删掉服务提供的DNS段落。
3. 仅恢复最近修改的一项DNS设置，重试同一目标，观察解析错误是否消失。
4. 在TUN、Fake-IP或分应用代理模式下，还要检查是否使用了与该模式匹配的DNS配置；配置问题交给服务方时附上脱敏错误。

**判断边界：**系统的`nslookup`结果不一定反映客户端内部的解析过程；直接访问IP可能因TLS证书和虚拟地址等原因失败，也不能单独证明DNS有问题。不要用一次系统解析结果替代客户端日志。

## 第七步：更换本地网络

保持设备、账号、配置、节点和测试目标不变，只把家庭宽带换成手机热点，重试一次订阅更新和实际访问。

- **热点可用、宽带失败：**记录两次结果，检查路由器、网络访问限制和本机软件差异；这是网络路径的线索，不能直接断言运营商封锁。
- **两种网络都失败、另一台设备可用：**优先对比当前设备的客户端版本、代理设置及VPN状态。
- **不同设备和网络都失败：**把账号状态、配置更新结果、节点名称与时间交给服务方核对。

对照后恢复日常网络和原先可用的配置。不要把全局代理、临时DNS或调试日志长期留作“修复”。

## 两个排查示例

### 示例一：更新成功，仍提示配置解析失败

观察：请求完成，但导入出现格式错误。先查看服务后台选的是Clash还是sing-box配置，再确认客户端要求的格式；如果响应是登录页面，应回到订阅请求检查。修正入口后，验证配置能读取且节点列表出现。这个过程不需要先修改DNS或购买新套餐。

### 示例二：网页可用，某个应用一直超时

观察：同一个节点下浏览器能访问目标。先在客户端记录一次应用请求：没有连接记录时检查代理接管和分应用排除；记录显示直连时检查规则；已经走代理但失败时比较另一个节点。找到差异后恢复原模式，保留需要调整的单项设置。

## 提交工单时提供什么

复制下面的记录结构，把占位内容换成自己的观察。不要填入私有订阅地址：

```text
发生时间及所在时区：
系统 / 客户端 / 核心版本：
当前网络（宽带或热点、运营商）：
症状及完整错误提示（已脱敏）：
账号有效期与剩余流量是否正常：
所选配置格式 / 节点 / 代理模式：
同设备换网络的结果：
同网络换节点或设备的结果：
已修改的单项设置及恢复结果：
```

客户端自身启动、服务安装或配置兼容问题可先查官方文档；服务端认证、套餐限制和节点维护问题则联系对应服务方。截图前遮住订阅地址、账号、订单号和私人访问记录。
