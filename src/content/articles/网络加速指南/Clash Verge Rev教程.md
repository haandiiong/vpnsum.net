这篇指南适合已经取得 Clash/Mihomo 订阅、准备在 Windows 或 macOS 上完成第一次连接的读者。Clash Verge Rev 是客户端，不会自行提供账号、节点或流量；只有服务商登录网址、专属客户端账号时，先确认是否另有兼容订阅。

资料核对日期为 **2026 年 10 月 14 日**，依据官方文档与官方发布页整理，未进行本站设备实测。下文错误是排查用的症状示例。菜单名称和位置可能随版本、语言与窗口宽度变化，找不到对应项目时可对照文末官方图示。

## 开始前保留什么

- **订阅来源：**从服务商后台复制明确标注为 Clash/Mihomo 的完整链接，不要把登录页或其他客户端格式当成订阅。
- **原来的网络设置：**记录系统代理、DNS 和其他 VPN 的状态。需要企业代理或公司 VPN 的设备，保留其原配置。
- **可回退的配置：**已有可用订阅时，记录当前配置、节点与模式；升级或修复服务前，使用“设置 → Verge 高级设置 → 备份设置”保留备份。不要先删除旧订阅再导入新订阅。
- **测试顺序：**先确认订阅与系统代理可用，再尝试 TUN。测试时只保留一个接管系统流量的客户端，避免把多个工具的结果混在一起。

订阅地址通常包含账户凭据。复制时不要删掉参数，提交截图或日志时则应遮住完整地址、二维码与令牌。

## 选择 Windows 或 macOS 安装包

从[官方仓库](https://github.com/clash-verge-rev/clash-verge-rev)进入 [Releases 正式版](https://github.com/clash-verge-rev/clash-verge-rev/releases/latest)。本次核对时，该入口指向 **v2.5.8**；后续下载请看发布页的支持范围，不把本文版本号当作永久最新版。首次安装优先选择正式版，而非标注 Pre-release 的测试版或 AutoBuild。

| 设备 | 先确认什么 | 在发布页选择什么 |
|---|---|---|
| Windows，Intel 或 AMD 的 64 位电脑 | “设置 → 系统 → 关于”中的系统类型 | 文件名含 `x64-setup.exe` 的普通安装包 |
| Windows on ARM 电脑 | 系统类型明确为 ARM64；不能只凭电脑品牌判断 | 文件名含 `arm64-setup.exe` 的安装包 |
| Mac，Apple M 系列芯片 | 苹果菜单“关于本机”显示 Apple 芯片 | 文件名含 `aarch64.dmg` 的安装包 |
| Mac，Intel 芯片 | “关于本机”显示 Intel 处理器 | 文件名含 `x64.dmg` 的安装包 |

Windows 当前发行版不支持 Windows 7；官方安装文档将 macOS 常规支持范围写为 **macOS 12 及以上**。旧系统、较老处理器或特殊安装方式请先核对[官方安装说明](https://www.clashverge.dev/install.html)，不要仅看“64 位”就判断兼容。

Windows 运行安装器并按提示完成安装，服务模式优先使用安装器默认目录；Mac 打开 DMG 后将应用放入“应用程序”。更新已有安装前，先从托盘或菜单栏退出旧进程，再安装新包。首次打开时按系统提示处理应用或服务授权。

Windows 如果只有托盘图标、点开却没有窗口，先按[官方 Windows FAQ](https://www.clashverge.dev/faq/windows.html)检查 WebView2 是否缺失或被禁用。发布页的 `fixed_webview2` 包内置运行环境，适合无法正常安装 WebView2 的情况；它不是所有人的默认下载项。

## 导入并启用订阅

1. 打开左侧 **“订阅”** 页面，将后台复制的完整地址粘贴到页面上方标注 **“订阅文件链接”** 的输入框，点击 **“导入”**。
2. 等待请求结束。应出现订阅配置卡片；如果只有报错通知而没有新卡片，停在这一步处理导入问题。
3. 点击准备使用的配置卡片，将它设为当前配置。导入成功与启用配置是两步，卡片存在不等于内核正在使用它。
4. 需要刷新时，在该卡片的菜单中选择 **“更新”**。观察更新时间与错误提示；不要连续点击更新掩盖第一条报错。
5. 进入 **“代理”** 页面，确认能看到该配置的策略组和节点。组名由订阅决定，可能是“节点选择”“代理”或服务商自定义名称。
6. 初次验证使用 **“规则”** 模式，在需要走代理的策略组中选一个实际节点，进行延迟测试。显示毫秒数只能说明测试请求有响应，不能证明所有应用都可用；“超时”也要结合下面的网页测试判断。

如果服务商提供的是配置文件而不是链接，可按[官方订阅导入说明](https://www.clashverge.dev/guide/profile.html)新建本地配置并选择文件，或使用该版本支持的文件拖入方式。本地文件不会因为服务商更新而自动变成远程订阅。

## 先用系统代理验证连接

在 **“设置 → 系统设置”** 中开启 **“系统代理”**，暂时关闭 **“虚拟网卡模式”**（TUN）。系统代理会修改操作系统的代理设置；浏览器通常会遵循这些设置，但某些应用有自己的网络选项。原理与图示见[官方快速入门](https://www.clashverge.dev/guide/quickstart.html)。

按下面顺序观察，不用“开关变亮”代替连接验证：

| 检查 | 如何观察 | 能说明什么 |
|---|---|---|
| 配置与内核 | “代理”页有可选节点，没有持续出现内核启动失败或配置解析错误 | 当前配置至少已加载；仍需检查请求是否接管 |
| 操作系统代理 | Windows 查看“设置 → 网络和 Internet → 代理”；Mac 查看“系统设置 → 网络 → 当前网络服务 → 详细信息 → 代理” | 代理地址、端口或自动配置方式应与客户端设置一致，不能指向另一款已退出的软件 |
| 普通网页 | 打开一个当前网络本来就能访问的网页，再刷新一次 | 开启代理后没有让基础网络失效 |
| 目标网页或应用 | 新开目标页面，并查看客户端的连接记录或日志中是否出现对应请求、匹配规则和出站节点 | 可判断请求是否由客户端处理；登录限制或平台报错仍要单独分析 |
| 持续使用 | 连续操作几分钟，再测试实际需要的应用 | 一次延迟成功不能替代连接是否持续可用的观察 |

如果要对照应用自己的代理设置，在客户端设置页面的端口配置项读取**当前运行端口**，不要直接套用网上固定的 `7890` 或 `7897`。规则模式下某些请求会直连，看到 DIRECT 不一定是故障，先确认该目标原本应该走哪条规则。

## 需要 TUN 时检查服务与权限

TUN 通过虚拟网卡接管更多流量，适合目标应用没有遵循系统代理的情况。它会影响路由和 DNS，开启前先确认系统代理已经能完成基本连接，并记录原 DNS 设置。

1. 在 **“设置 → 服务模式”** 查看当前状态；未安装或需要修复时，按应用提示安装或修复服务，并完成操作系统要求的管理员授权。
2. 授权后检查应用是否确认服务模式可用、内核能正常启动。若仍显示安装失败、安全检查失败或普通模式，先保留原始提示，不要反复开关 TUN。
3. 再开启 **“虚拟网卡模式”**（TUN）。保持同一订阅、节点和规则，重新测试普通网页及之前失败的应用，避免同时切换节点或改 DNS。
4. TUN 可用后，再按需求决定是否保留系统代理。两者同时开启也不等于所有请求必然走代理，仍由规则和应用行为决定。

**Windows：**官方 FAQ 说明，普通权限的 Sidecar 模式不能使用 TUN。优先恢复服务模式；需要临时对照时，可先完整退出应用，再右键快捷方式选择“以管理员身份运行”，按官方说明继续使用 Sidecar 后测试 TUN。这不会修好安装目录的权限，之后仍需处理服务模式提示。修复前先备份，详细步骤见[官方服务安全检查说明](https://www.clashverge.dev/faq/windows.html)。

**macOS：**服务安装和修改系统网络设置可能需要管理员授权。若授权被拒绝或受管理设备禁止安装服务，先保持已验证的系统代理方式，记录提示交给设备管理员核对；不要通过关闭整套安全防护来试错。官方文档说明 TUN 会调整系统 DNS，因此测试后也要检查 DNS 是否恢复。

## 按症状排查，先保留可用状态

下面是症状示例，不是本站已复现的故障记录。每做一次修改，都重复同一个测试；失败就恢复上一状态。

| 症状 | 第一个检查动作 | 接着观察与回退 |
|---|---|---|
| 导入或更新提示 `client error(Connect)` | 确认完整链接、账号有效及系统时间正常；查看错误发生在下载还是解析阶段 | 换已知可用网络对照；已存在的订阅且已有可用代理时，可尝试卡片菜单的“更新（代理）”。首次导入没有卡片时，对照官方导入说明中的其他方式；保留旧卡片，不把关闭证书校验作为默认办法 |
| 下载成功但配置解析失败 | 确认后台交付的是 Clash/Mihomo 配置，而非登录页、其他订阅格式或空文件 | 新配置不启用，切回原配置；把脱敏后的解析错误与客户端版本提供给服务商 |
| 一个节点超时，其他节点可用 | 在同一策略组换另一个节点 | 新节点能完成同一网页测试时，暂用它；记录失败节点、时间与网络，避免重装客户端 |
| 全部节点超时 | 先查套餐与流量，再核对当前配置，关闭 TUN 用系统代理对照 | 同一设备换手机热点，或同一账号换另一设备；差异用于缩小故障范围，不能仅凭“全红”认定服务停运 |
| 浏览器可用，某个应用不可用 | 查看该应用是否有自己的代理设置，及客户端是否收到对应请求 | 先检查匹配规则和应用代理；确有接管需求时再按上节验证 TUN，失败便关回 TUN |
| 一开 TUN 就断网 | 先关闭 TUN，回到之前可用的系统代理、节点和规则 | 基础方式恢复后再查看服务、权限、虚拟网卡与 DNS 提示；不要批量删除网卡或同时替换多项网络设置 |
| 退出客户端后普通网页也打不开 | 检查系统是否仍指向已停止的本地代理 | 按下一节恢复原代理设置；若 Mac 仍不能解析域名，继续核对原 DNS 与当前值 |

## 断网后恢复原设置

先在应用内关闭 TUN，再关闭系统代理，从托盘或菜单栏完整退出。重新访问原来能打开的普通网页。如果仍失败，检查操作系统中的残留设置：

- **Windows：**进入“设置 → 网络和 Internet → 代理”。如果原本没有手动代理，关闭本次由客户端启用且仍指向本机的“使用代理服务器”；原来有企业代理或自动配置脚本时，按开始前记录恢复，不能一律清空。
- **macOS：**进入“系统设置 → 网络 → 当前网络服务 → 详细信息 → 代理”，恢复开始前记录的 HTTP、HTTPS、SOCKS 或自动配置状态。在同一网络服务的 **DNS** 页面核对服务器列表，仅撤回本次新增或修改的值，不删除原有工作网络配置。旧版 macOS 的入口可能在“系统偏好设置 → 网络 → 高级”。

操作入口分别见 [Apple 代理设置](https://support.apple.com/zh-cn/guide/mac-help/mchlp2591/mac)和 [DNS 设置](https://support.apple.com/zh-cn/guide/mac-help/mh14127/mac)。[v2.5.8 发布说明](https://github.com/clash-verge-rev/clash-verge-rev/releases/tag/v2.5.8)记录了 macOS 关闭 TUN 或退出后 DNS 残留的修复；遇到同类现象时，先记录应用版本和残留值，再决定是否按官方说明更新。

如果停用客户端、恢复原代理与 DNS 后仍然失败，转向检查本地网络。保留已恢复的状态，不继续添加临时规则；可按[订阅与连接故障排查](/guides/subscription-troubleshooting/)进行设备和网络对照。

## 留下能帮助定位的记录

在应用的日志页面复现一次问题，记录时间、系统版本、客户端版本、模式、所选节点和第一条错误。日志中的订阅地址、账户、访问令牌以及私人访问记录应先脱敏。

需要文件日志时，进入 **“设置 → Verge 高级设置 → 日志目录”**。按[官方导出日志指南](https://www.clashverge.dev/guide/log.html)提高相应日志级别后重新启动，再重复失败动作，选择当日对应日志。GUI 与 `service` 目录中的内核日志用途不同，提供与问题相关的文件；结束后将日志级别恢复为 INFO。

记录可以按“操作前状态 → 修改一项 → 观察结果 → 是否回退”整理。这样服务商或项目维护者能区分配置、服务权限和网络问题，也便于自己恢复，而不是只能收到“不能用”三个字。
